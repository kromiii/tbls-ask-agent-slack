# tbls-ask-agent-slack

A Slack bot powered by [tbls-ask](https://github.com/k1LoW/tbls-ask) that answers natural language questions about your database schemas by generating SQL queries.

<img width="869" alt="image" src="https://github.com/user-attachments/assets/1a0657d8-16a4-4f8f-b040-80a3093e36c2">

## Features

- **Natural Language to SQL**: Mention the bot and ask questions in plain English (or other languages). It returns ready-to-run SQL queries.
- **Multiple Schemas Support**: Configure multiple databases; the bot lets you select target schemas via interactive Slack dropdowns.
- **Socket Mode**: Uses Slack Socket Mode—no public endpoint or reverse proxy required.
- **Flexible LLM Providers**: Supports OpenAI as well as OpenAI-compatible APIs (e.g., Google Gemini, Ollama, OpenRouter).
- **Safe by Design**: Generates SQL queries without directly executing them against your database.

## How It Works

1. **Mention**: A user mentions `@tbls-ask` with a question in a Slack channel or thread.
2. **Schema Selection** *(if multiple schemas configured)*: The bot prompts you to select a schema or query all schemas.
3. **Prompt Generation**: Schema definitions generated by [`tbls`](https://github.com/k1LoW/tbls) and conversation history are combined into an LLM prompt.
4. **SQL Response**: The bot replies in the thread with the generated SQL query.

> [!NOTE]
> **Limitations**
> - The bot only generates SQL queries; it **does not execute** them directly on your database. Run the query against your database to get the actual results.
> - Database schema files (`schema.json`) must be prepared beforehand using [`tbls`](https://github.com/k1LoW/tbls).

## Usage

Invite the bot to your desired Slack channels, then mention it with your question:

```
@tbls-ask name of the users who has the most stars
```

The bot will respond in the thread with an SQL query that answers your question.

### Multiple Schemas Support

If you have configured multiple schemas in `schemas/config.yml`:

1. Mention the bot with your question.
2. The bot responds with a dropdown menu to select the target schema (or "All").
3. Select the schema you want to query against.
4. The bot generates the SQL query based on the selected schema.

## Setup Guide

### 1. Create a Slack App

1. Go to [Slack API: Your Apps](https://api.slack.com/apps) and click **Create New App**.
2. Select **From an app manifest**.
3. Choose your workspace and paste the contents of [`manifest.yml`](manifest.yml).
4. Go to **Install App** in the sidebar and install the app to your workspace. Copy the **Bot User OAuth Token** (`xoxb-...`).
5. Go to **Basic Information** > **App-Level Tokens** and click **Generate Token and Scopes**. Add the `connections:write` scope, generate the token, and copy the **App-Level Token** (`xapp-...`).

### 2. Prepare Schemas

Create schema documents using [`tbls`](https://github.com/k1LoW/tbls) (e.g., `tbls out -t json -o schema.json`).

Copy the sample schema configuration and edit it:

```sh
cp schemas/config.yml.sample schemas/config.yml
```

Example `schemas/config.yml`:

```yaml
schemas:
  - name: "wordpress"
    path: "https://raw.githubusercontent.com/k1LoW/tbls-ask/main/testdata/wordpress.json"
  - name: "test"
    path: "https://raw.githubusercontent.com/k1LoW/tbls/main/sample/mysql/schema.json"
```

*Note: `path` can be a local file path, a remote URL, or a private GitHub repository path (requires `GITHUB_TOKEN`).*

### 3. Environment Variables

Copy `.env.sample` to `.env` for local development:

```sh
cp .env.sample .env
```

Configure the environment variables:

| Variable | Required | Default | Description |
|---|---|---|---|
| `SLACK_APP_TOKEN` | **Yes** | - | Slack App-level token (`xapp-...`, requires `connections:write`) |
| `SLACK_OAUTH_TOKEN` | **Yes** | - | Slack Bot User OAuth token (`xoxb-...`) |
| `OPENAI_API_KEY` | **Yes** | - | API key for OpenAI (or OpenAI-compatible API) |
| `MODEL_NAME` | No | `gpt-4o` | LLM model name (e.g., `gpt-4o`, `gpt-4o-mini`, `gemini-flash-latest`) |
| `OPENAI_BASE_URL` | No | - | Base URL for OpenAI-compatible endpoints (e.g., `https://generativelanguage.googleapis.com/v1beta/openai/`) |
| `CUSTOM_INSTRUCTION` | No | - | Custom system instruction for the LLM (e.g., `"Always Respond in Japanese"`) |
| `DEBUG_MODE` | No | `false` | When set to `"true"`, logs prompt contents to stdout |
| `GITHUB_TOKEN` | No | - | GitHub personal access token (for remote schemas on GitHub) |
| `GH_HOST` | No | - | Host for GitHub Enterprise Server (e.g., `git.example.com`) |
| `GITHUB_ENTERPRISE_TOKEN` | No | - | Access token for GitHub Enterprise Server |

## Running Locally

Start the server with:

```sh
make server
```

*(or `go run main.go server`)*

Because the app uses Slack Socket Mode, you do not need to expose your server to the internet or configure `SLACK_SIGNING_SECRET`.

## Deploy to Kubernetes

You can deploy `tbls-ask-agent-slack` to Kubernetes using the Helm chart in [`charts/tbls-ask-agent-slack`](charts/tbls-ask-agent-slack).

### Quick Start with Makefile

1. Build the Docker image locally (if needed):
   ```sh
   make build-image
   ```

2. Deploy using Helm (uses environment variables and `schemas/config.yml`):
   ```sh
   make helm-deploy
   ```

To uninstall:
```sh
make helm-uninstall
```

### Deploy directly with Helm

```sh
helm upgrade --install tbls-ask-agent-slack ./charts/tbls-ask-agent-slack \
  --set secret.slackAppToken="$SLACK_APP_TOKEN" \
  --set secret.slackOAuthToken="$SLACK_OAUTH_TOKEN" \
  --set secret.openaiApiKey="$OPENAI_API_KEY" \
  --set secret.githubToken="$GITHUB_TOKEN" \
  --set config.openaiBaseUrl="$OPENAI_BASE_URL" \
  --set-file schemas.config=schemas/config.yml
```

Or customize settings with a custom `values.yaml`:

```sh
helm upgrade --install tbls-ask-agent-slack ./charts/tbls-ask-agent-slack -f my-values.yaml
```

See [values.yaml](charts/tbls-ask-agent-slack/values.yaml) for all configurable parameters, including using existing Secrets / ConfigMaps and resource limits.
